# notch-utils — Sub-project B: Simple Modules

Date: 2026-10-31. Status: approved in chat, implemented on branch `modules-b`.

## Calculator (`calc`)
macOS basic calculator: AC/C, ±, %, ÷ × − +, =, decimal. Operator precedence, repeated `=`,
`%` relative to a pending + / −, 9-digit entry, "Error" on division by zero. Keyboard input
while the notch is expanded (digits, + - * /, Enter, Backspace, Delete; Esc still collapses).
Pure `Engine`, unit-tested. Layout: display left of the keypad so it fits 280 px height.

## Stats (`stats`)
`sysinfo` + `starship-battery`. 1 Hz only while visible; handles dropped on hide.
- `graphs` (default): CPU, memory, network cards with 60-sample bar charts.
- `detailed`: per-core CPU, disks, battery, temperatures (where exposed), top 5 processes.
  Disk/sensor/battery probes are created only in this view.

## Clipboard (`clipboard`)
`clipboard-rs` watcher (macOS polls `changeCount` every 500 ms; Windows/X11 event-based).
Runs only while the module is enabled; disabling stops it and clears memory.
- Text + images, dedupe (re-copy moves to top), pins, search, clear (keeps pins).
- Limits: `max_entries` unpinned entries (default 50), 64 MB raw image budget, 1 MB text.
- Secrets skipped: `org.nspasteboard.{Concealed,Transient,AutoGenerated}Type`,
  `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`,
  `x-kde-passwordManagerHint`.
- Click copies back and collapses the notch.
- `persist = true`: text + pins saved to `<data dir>/clipboard.json` (0600, atomic write);
  images never saved; file deleted when persist is turned off.

## Config
```toml
[modules.stats]
view = "graphs"     # graphs | detailed
[modules.clipboard]
max_entries = 50
persist = false
```
Defaults: all four modules enabled; expanded height 300.

## Module API additions
`Module::key(&str) -> bool`, `Module::config_changed(&Config)`, `Ctx::collapse`.

## Found along the way
- winit 0.30.13 aborts on macOS during rapid resizes (KVO `expect` in an extern "C"
  callback). Vendored with a 3-line fix in `vendor/winit`.
- The GL renderer costs a ~230 MB transient peak at startup (driver init); the software
  renderer peaks at ~37 MB but uses ~2x CPU during animations. Decision pending.
